# 日月 编译器差距补齐计划

> 本文档是「日月 vs 主流语言」对比结论（见 `文档/语言对比分析.md`）的**落地计划**，
> 统一收口此前分散的计划（`.trae/documents/优化方案与语言能力补全.md`、`文档/内存安全方案.md`、`文档/短板补齐计划.md`）。
> 目标：把日月从「语义完整、优化与调试为零」推进到「生产可用编译器」。

---

## 一、目标与原则

**目标**：补齐对比中暴露的能力差距，优先级由「影响可用性」决定。

**原则**：
1. **中文优先**：新增文件名/内容/IR 关键字一律中文，不符合中文的先改。
2. **双编译器一致**：任何 codegen 改动必须同时改**宿主**（`源/后端/*.cpp`）与**自举**（`自举/发射.心`、`自举/语法_树.心`），保持 `make 自举` 不动点（`中间码1.ll == 中间码2.ll`）。
3. **护栏优先**：每阶段结束回归须 `Pass ≥ 92 / Fail = 0`，且不动点成立。
4. **不并发编译**：`run_tests.sh` 的清理逻辑会杀 `日月/clang++/llc/ld`，编译/测试串行执行。
5. **可验证**：每项交付须有验证方法与证据。

## 七、风险与约束

1. **不动点约束**：宿主与自举 codegen 必须逐字一致，阶段 1/2/3 的 codegen 改动工作量因**双份实现**而翻倍。

5. **LLVM 本地化依赖**：调试/优化元数据的汉化取决于本地化 LLVM 23，需同步维护 `llvm-project` 改动。
6. **不并发编译**、**中文文件名**等既有约束继续适用。

## 九、构建速度优化（工程项，可立即落地）

### 9.1 实测基线（本机 18 核）

| 环节 | 耗时 | 备注 |
|---|---|---|
| **宿主构建 `引导.exe`（`build.sh`）** | **75.4s** | ← 唯一瓶颈 |
| ├ 12 个 .cpp 串行编译（含 `-g`） | ≈63s | 单文件 ~5.25s × 12 |
| ├ 运行时 .c + 链接（GNU ld） | ≈ 3.2s 链接 | 产出 89MB |
| **自举构建 `日月.exe`** | **2.2s** | 非瓶颈 |
| 全套合计 | ≈77s | |

### 9.2 瓶颈定位（实测）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **`-g` 调试信息** | 单 TU 含 `-g` 5.25s vs 无 `-g` 1.46s | **3.6×** |
| 2 | **串行编译** | 12 TU 串行 63s → 并行(18核) 6.66s | **9.5×** |
| 3 | **默认 GNU ld** | GNU ld 3.15s vs `-fuse-ld=lld` 1.18s | 2.7× 链接 |
| 4 | **无 PCH / 无 ccache** | 9.4k 行源码却每 TU 重解析全部 LLVM 头 | 增量每次全量 |
| 5 | **无头依赖追踪** | `build.sh` 无条件重编全部；Makefile 无 `-MMD` | 改 1 文件也 75s |
| 6 | 自举编译 | 2.2s | 不用动 |

**关键洞察**：宿主源码仅 9.4k 行，慢的不是代码量，而是「每 TU 重复解析庞大 LLVM 头 + `-g` 海量调试信息 + 串行 + 全量重编」。

### 9.3 优化措施与预期收益

| 措施 | 改法 | 预期 |
|---|---|---|
| **A. 并行编译** | `build.sh` 用 `&`+`wait`，或 `make -j18 引导` | 63s → 6.7s |
| **B. 去掉 `-g`**（另设调试构建） | CXXFLAGS 移除 `-g` | 再省 3.6× |
| **C. lld 链接** | 链接加 `-fuse-ld=lld` | 3.15s → 1.2s |
| **D. 头依赖 + 增量** | `-MMD -MP` + `include *.d` | 改 1 文件只重编 1 个 |
| **E. PCH（可选）** | 预编译 LLVM 头为 `.pch` | 单 TU 再降 |
| **F. ccache（可选）** | `CXX="ccache clang++"` | 增量 ~1s |

**组合 A+B+C 后预期**：宿主构建 **75s → ≈3s**；全套 **77s → ≈5s**；加增量（D）改 1 文件约 **1s**。

### 9.4 建议改动

- **`build.sh`**：12 条 `clang++ -c ... &` + `wait`；CXXFLAGS 去 `-g`；链接加 `-fuse-ld=lld`；脚本内 `export MSYS2_ARG_CONV_EXCL='*'`。
- **`Makefile`**：`引导` 目标递归 `$(MAKE) -j$(nproc)`；CXXFLAGS 去 `-g`、加 `-MMD -MP` 并 `-include $(ALL_OBJ:.o=.d)`；链接加 `-fuse-ld=lld`。

### 9.5 注意

1. 去 `-g` 不影响生成代码正确性，只影响编译器自身可调试性（可留独立「调试」构建）。
2. 并行编译与测试阶段（`run_tests.sh` 会杀进程）**不可同时进行**。
3. **本地化 LLVM（`llvm-build`）另计**：3589 目标文件、792MB 静态库、`clang++.exe` 206MB；改其 `.cpp` 会触发对应库重编 + 一大批巨型可执行文件重链，单轮可达 20–40 分钟（见对话说明）。日月自身两条链不受此影响。

### 9.6 实测结果（已落地）

| 环节 | 优化前 | 优化后 | 措施 |
|---|---|---|---|
| **宿主构建 `引导.exe`（`build.sh`）** | **75.4s** | **≈8.3s** | A 并行 + B 去 `-g` + C lld |
| ├ 12 个 .cpp 编译 | ≈63s 串行 | ≈6.7s 并行 | `&`+`wait` |
| ├ 运行时 .c + 链接 | GNU ld 3.2s | lld 1.2s | `-fuse-ld=lld` |
| 自举 `日月.exe`（种子编译一次） | 2.2s | 2.1s | — |
| **自举闭环 `make 自举`（阶段一/二）** | **≈30 分钟** | **≈50s** | 见 9.7 |

> 说明：实际 8.3s 高于 9.3 的乐观预测（≈3s），因即便去掉 `-g`，每个 TU 仍需解析庞大 LLVM 头，构成固定成本；PCH/ccache（D/E/F）可进一步下降，但非当务之急。

### 9.7 自举编译（阶段一/阶段二）「卡半小时」的根因与修复

「阶段一」（`一级.exe` 编译自身得 `中间码1.ll`）与「阶段二」（`二级.exe` 编译自身）此前各需十几分钟、内存数 GB。经定位，热点**既非 `llc -O2`，也非宿主**，而是自举编译器自身运行的**两处 O(n²)**：

| # | 位置 | 原因 | 修复 |
|---|---|---|---|
| 1 | 自举 `处理导入`（`自举/编译器.心`） | 逐行 `结果 + 行 + "\n"` 拼接：日月 `+` 每次 malloc 新串并整体拷贝，O(n²) 且永不释放（内存 3GB） | 改用「文本缓冲」句柄累加（O(1) 摊薄追加），错误状态用全局标志承载 |
| 2 | 运行时 `字符码`（`源/运行时/运行时辅助.c`） | 每次取码点都从串首重扫，O(位置)；PEG 分词在每个字符位置对数十条模式反复取码点 → O(n²) | 对「长串」按指针缓存 字符索引→字节偏移（命中 O(1)）；短串/静态缓冲仍走扫描 |
| 3 | 运行时 `字符位置到字节位置`（供 `子串` 内联调用） | 同样从串首重扫，O(位置)；分词逐 token 按当前位置切子串 → O(n²) | 复用同一 字符索引 缓存，O(1) |
| 4 | 运行时 `获取行` | 每次从串首重扫到目标行，「逐行遍历全文」= O(n²) | 增设按指针的行游标，顺序取行时续扫，整趟遍历 O(n) |

**安全性要点**：按指针缓存的前提是「串内容不可变」。运行时存在多处「地址固定、内容可变」的 `static char` 缓冲（`获取行`/`读取文件`/路径拼接等），故新增「静态缓冲登记表」，这些地址一律不参与缓存（否则同址换内容会命中陈旧索引，导致解析失败）。

**实测（规模扫描，N 行平凡源，单文件）**：

| 行数 | 修复前 日月.exe | 修复后 日月.exe | 修复前 引导.exe | 修复后 引导.exe |
|---|---|---|---|---|
| 2000 | 2.32s | 1.56s | 0.70s | 0.70s |
| 8000 | 13.62s | 3.71s | 0.97s | 0.96s |
| 32000 | 165.25s | **12.70s** | 5.44s | 2.33s |

修复后 `日月.exe` 编译耗时随规模近似线性增长（2×规模 ≈ 1.9×耗时），不再是平方级。

**回归与一致性验证**：`make 自举`（不动点 `中间码1.ll == 中间码2.ll`）通过；`run_tests.sh` 全量 **Pass 87 / Fail 0**；`llvm-as` 位码往返一致；T5 token id 宿主↔自举对照 86 样例全通过。
