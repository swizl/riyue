> 现状评估（2026-10-26）：语言与 AI 的结合深度约 **2/10**，工具链可协作性约 **6/10**。本 Phase 按「先补可机读面 → 再补验证闭环 → 最后补语言原语与生态」推进；能纯 `.心` 落地的一律不改编译器（保持不动点恒定）。

### 9.1 结构化诊断（`--json`）
- `诊断` / `检查` / `测试` 增加 `--json` 开关，输出 `{文件, 行, 列, 严重级, 错误码, 消息}` 数组
- 退出码与文本模式保持一致（有错误 → 1）
- 复用 `标准库/JSON.心`，**纯 `.心`**，不改编译器

**未实现/当前状态（🟡 部分实现——9.1 主体已落地）**：三条子命令的 `--json` 均已接通，**纯 `.心`**、不改编译器。
- `检查 [--json] [--递归] 输入|目录`（`工具/代码检查器.心` 模块版本 4）：`{"files":N,"errors":M,"diagnostics":[{file,line,severity,message}…]}`；JSON 模式不打印文本提示、有错误仍退出码 1。
- `诊断 [--json] 输入.心`（`工具/统一命令行.心`）：调用 `日月.exe` 编译、把 stdout/stderr 重定向到临时日志再逐行解析，输出 `{"exit":N,"errors":E,"warnings":W,"notes":T,"diagnostics":[{file,line,column,severity,message}…]}`；严重级取行首 `错误`/`警告`/`注意`（→ `error`/`warning`/`note`），`[文件]` 与 `（行 N:列）` 可缺省；`errors > 0` 时 `exit` 归一为 1 且进程退出码 1；临时日志与 `.exe`/`.ll`/`.bc` 产物用完即删；文本模式原样回放编译器日志（退出码同上）。
- `测试 [--json] [过滤词]`（`工具/测试运行器.心` 模块版本 3 新增 `测试明细项`/`测试运行目录明细`）：`{"suites":N,"passed":P,"failed":F,"skipped":S,"passRate":R,"tests":[{name,status}…]}`，`status` ∈ `passed`/`failed`/`skipped`，套件按路径升序；`passRate` 与文本汇总同口径（通过/(通过+失败)，四舍五入）。
- **仍待补**：字段尚无 `错误码`（编译器诊断无码位）；`检查` 无 `列`（其规则只到行）；JSON 为手写拼装（`标准库/JSON.心` 只有键值助手、无数组组装），单行扁平输出；套件名假定不含 `"`/`\`（不转义）；编译器把个别标识符另起一行输出（如 `错误: 未声明的标识符: ` 后单独一行 `甲`），该行不以级别词开头故被过滤、`message` 末段留空——属编译器输出格式限制，需改 `源/前端/诊断.cpp` 才能彻底解决。
- 后续：9.2 LSP 扩容、9.3 验证闭环、9.4 语言内 AI 原语均已完成 → 9.5 生态。

### 9.2 LSP 扩容与跨文件索引
- `semanticTokens`（语义高亮）、`workspaceSymbol`（全工程符号）
- 跨文件 `definition` / `references`（当前仅单文件内）
- 增量同步（`textDocument/didChange` 由全量改为增量）

**当前状态（✅ 已落地——9.2 四项全部完成，纯 `.心`、不改编译器）**：`工具/LSP会话.心` 模块版本 11→**14**，`工具/LSP报文.心` 方法序号扩至 **17**、能力清单增两项。
- **语义高亮** `textDocument/semanticTokens/full`（版本 11）：新增 `找码位` / `追加令牌` / `语义令牌对象`，输出 LSP 标准 5 元组相对编码 `[deltaLine, deltaStart, length, type, modifiers]`；类型表 9 项（0 keyword / 1 function / 2 struct / 3 enum / 4 number / 5 string / 6 comment / 7 variable / 8 method），`modifiers` 恒 0；能力声明 `semanticTokensProvider`（legend.tokenTypes 同序、tokenModifiers 空、`full:true`）。
- **全工程符号** `workspace/symbol`（版本 12）：新增 `工作区符号对象` / `文档符号信息项`，遍历 `didOpen` 登记的全部文档、复用 `取声明` 识别（`函数` kind 12、`结构体` kind 23、`枚举` kind 10、`变量` kind 13 等）；能力声明 `workspaceSymbolProvider:true`。
- **跨文件跳转 / 引用**（版本 13）：工作区表以「`<uri>` + `(31)` + `<文本>` + `(30)`」顺序拼接存于纯字符串（同 uri 就地替换），新增 `工作区登记` / `工作区取` / `跨文件定义对象` / `收集引用` / `跨文件引用对象`；`definition` 先查本地、本地首个出现与光标词不同则遍历其它文档取首个独立出现；`references` 汇总全工作区独立出现处。
- **增量同步**（版本 14）：`didChange` 带 `contentChanges[].range` 时走新增 `应用增量`（`找串` 定位 + 前段/插入串/尾段三段拼接，按字符偏移处理），无 range 仍整文替换；`didOpen` 全量登记。
- **验证**：`示例/LSP服务端测试.心` 807→1121 行、续增 12 段断言（41–52，覆盖方法表 16/17 正反查、语义令牌、workspace/symbol、跨文件 definition/references、range 增量前后令牌对比）；`.期望` 重算（7,060→9,514 字节，版本 10→14、initialize 正文 393 字符 / 407 字节 / 声明长 407；references 现含跨文件 8 条）。`bash run_tests.sh` **207/0**；`bash 不动点验证.sh` 成立、值**不变**（6,078,606 字节 / `f623d43f0d8dcb80c451a3e41765105079535dd71b10fa7361b0daf64655ad9c`）。
- **限制**：语义令牌按**字符偏移**计（辅助平面字符与 LSP UTF-16 有偏差）；类型判定为**行级启发式**；工作区索引只覆盖 `didOpen` 过的文档（未主动扫描文件夹）、随进程内存增长且无上限；`workspace/symbol` 无查询词过滤（返回全量，由客户端过滤）；增量为**单次 range 替换**（多段 `contentChanges` 只取首段）。

### 9.3 AI 验证闭环
- 统一 `验证` 子命令：编译 + 运行 + 全量回归 + 不动点，输出机器可读报告
- 报告含失败用例、首个失败点、IR 大小与哈希，供 AI 修改后**自检**

**当前状态（✅ 已落地——`验证 [--json]`，纯 `.心`、不改编译器）**：
- 新增 `工具/验证报告.心`（模块版本 1）：解析两门禁日志，提取 `Pass/Fail`、首个失败点（`FAIL:` / `TIMEOUT:`）、`门禁: 通过`、不动点字节数与 `SHA256` 及两份哈希是否一致，并组装单行 JSON 报告。
- `工具/统一命令行.心` 升 v1.3，新增 `验证 [--json]`：先跑 `bash run_tests.sh`、再跑 `bash 不动点验证.sh`，日志重定向到 `阶段/回归.log` / `阶段/不动点.log`（GUI 无 stdout 时自动回退到 `C:/tools/msys64/usr/bin/bash.exe`），随后解析并输出；文本模式打印四行摘要（含首个失败点），任一门禁未通过则退出码 1。
- 报告结构：`{"ok":B,"tests":{"pass":P,"fail":F,"gate":B,"firstFailure":"…"},"fixpoint":{"bytes":N,"sha256":"…","gate":B},"logs":{"regression":"…","fixpoint":"…"}}`，供 AI 修改后**自检**。
- 实测（2026-10-26）：`验证 --json` → `pass=207 fail=0 gate=true`；不动点 `6,078,606` 字节 / `f623d43f0d8dcb80c451a3e41765105079535dd71b10fa7361b0daf64655ad9c` / 一致；`rc=0`。纯解析回归见 `示例/验证报告测试.心`（23 条断言）。
- 已知限制：解析依赖 bash 脚本文本格式（改动输出措辞需同步）；JSON 由本地助手手写拼接（仅转义 `"` `\` `\n` `\r` `\t`）；只覆盖回归与不动点两门禁，不含单次编译诊断（后者走 `诊断 --json`）。

### 9.4 语言内 AI 原语
- `标准库/AI.心`：LLM 客户端（走 `标准库/HTTP.心`，纯 `.心`），`AI补全` / `AI生成` / `AI解释`
- MCP 工具调用：JSON-RPC over stdio 对接外部工具
- `@约束模型输出`：复用 8CE 契约（`要求` / `确保`）校验模型返回的结构

**当前状态（✅ 已落地——三项全部完成，纯 `.心`、不改编译器）**：新增 `标准库/AI.心`（模块版本 1），导入 `JSON解析.心` / `HTTP.心` / `网络.心` / `契约.心`，共 7 组能力：
- **提示构造**：`AI补全提示(任务, 输入)` / `AI生成提示(需求)` / `AI解释提示(代码)`。
- **请求体**：`AI请求体(模型, 提示, 最大令牌)` → OpenAI 兼容 `chat/completions` JSON（转义复用 `JSON解析.心` 的 `JSON转义字符串`）。
- **响应解析**：`AI提取内容(响应)` 取 `choices[0].message.content`、`AI提取错误(响应)` 取 `error.message`（嵌套 JSON 走 `JSON解析.心` 节点池）。
- **收发与高层**：`AI拆分端点(端点)` 剥离 `http://` / `https://`、缺端口按 80、缺路径按 `/`；`AI发送(端点, 密钥, 体)` 用 `HTTP构造请求` + `网络.心` TCP 收发 + `HTTP解析响应`；`AI补全` / `AI生成` / `AI解释` 三高层函数（非 200 归空串）。
- **MCP（JSON-RPC 2.0）**：报文构造 `MCP请求` / `MCP通知` / `MCP初始化`（protocolVersion 2024-11-05）/ `MCP工具列表` / `MCP工具调用` / `MCP响应` / `MCP错误响应`；报文提取 `MCP取编号` / `MCP取结果` / `MCP是否错误` / `MCP取错误消息`；行式 stdio 传输 `MCP追加行` / `MCP取行` / `MCP行数`（以文件承载，便于离线回归）。
- **契约**：`AI结构合法(输出)`（去空白 + 可解析 + 根为对象）、`AI约束模型输出(输出, 说明)`（复用 8CE `确保`，通过印 ✓、违背印 ✗，归返 1/0）。
- **验证**：`示例/AI原语测试.心` 43 条断言（提示构造 / 请求体 / 响应解析 / 端点拆分 / MCP 7 种报文 + 提取 + 行传输 / 契约校验），`.期望` 1,462 字节；`bash run_tests.sh` **208/0**；`bash 不动点验证.sh` 成立、值**不变**（6,078,606 字节 / `f623d43f0d8dcb80c451a3e41765105079535dd71b10fa7361b0daf64655ad9c`）。
- **限制**：传输仅明文 `http://`（无 TLS），无连接复用；响应以 `Connection: close` + 循环接收（上限 64 次、每次至多 4095 字节）；模型输出不确定，调用方须自行重试；MCP 未与子进程直连（文件承载 stdio）；密钥以参数传入，不读环境变量。
