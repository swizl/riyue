# 日月编译器综合改进计划

## 概述

本计划覆盖日月编译器的六大改进领域：代码清理、构建系统、错误诊断、测试框架、类型系统、模块系统。
与现有 `重构计划.md` 互补——本计划聚焦其未覆盖的领域（错误诊断、测试、构建、类型、模块），
对其已覆盖的代码去重和缺失功能（do-while、return、import）仅做引用。

**依赖关系图**:
```
Phase 0: 代码清理（无依赖）
    ↓
Phase 1: 构建系统（依赖 Phase 0 清理 .o 文件）
    ↓
Phase 2: 错误诊断（依赖 Phase 1 验证构建）
    ↓
Phase 3: 测试框架（依赖 Phase 1 + Phase 2）
    ↓
Phase 4: 类型系统（依赖 Phase 2 错误报告 + Phase 3 测试）
    ↓
Phase 5: 模块系统（依赖 Phase 2 + Phase 4）
```

## Phase 2: 错误诊断

**目标**: 让编译器错误信息对用户友好——包含源码上下文、列号，codegen 错误包含行号。

### Task 2.1: 引入统一错误报告基础设施

**创建文件**: `源/前端/诊断.h`

```cpp
#ifndef 诊断_H
#define 诊断_H

#include <string>
#include <vector>
#include <iostream>

struct 源位置 {
    int 行号;
    int 列号;
    std::string 文件名;
};

struct 诊断信息 {
    enum 级别 { 错误, 警告, 注意 };
    级别 等级;
    源位置 位置;
    std::string 消息;
    std::string 源码行;     // 出错的源码行内容
    std::string 指示符;     // "^~~~~" 下划线
};

class 诊断引擎 {
    std::string 源代码;
    std::string 文件名;
    std::vector<诊断信息> 诊断列表;

public:
    void 设置源码(const std::string& 源码, const std::string& 文件);
    void 报告错误(int 行号, int 列号, const std::string& 消息);
    void 报告错误带上下文(int 行号, int 列号, int 长度, const std::string& 消息);
    void 输出所有(std::ostream& 输出 = std::cerr) const;
    bool 有错误() const { return !诊断列表.empty(); }
    int 错误数量() const { return (int)诊断列表.size(); }

private:
    std::string 提取行(int 行号) const;
    std::string 生成指示符(int 列号, int 长度) const;
};

#endif
```

**创建文件**: `源/前端/诊断.cpp`

实现要点:
- `提取行()`: 从源代码中按行号提取一行文本
- `生成指示符()`: 在列号位置生成 `^` 和 `~` 下划线
- `输出所有()`: 输出格式如:
  ```
  错误[语法分析器]: 期望分号（文件.心:5:12）
    5 | 变量 x = 1
      |            ^
  ```

**验证**: 编写单元测试验证 `诊断引擎` 的输出格式。

## Phase 4: 类型系统（渐进式改进）

**目标**: 添加基本的编译期类型检查，不破坏现有功能。

### Task 4.1: 类型标注解析增强

**当前状态**: 类型标注（如 `: 整数`）在解析时被接受但大部分被忽略。
`符号表` 中的 `变量类型信息` 已有 `变量类型种类` 枚举，但赋值时不检查一致性。

**修改文件**: `源/后端/代码生成器_语句.cpp`

在 `变量声明` case 中，当有类型标注时，检查初始值类型是否匹配:

```cpp
case 语句类型::变量声明: {
    const auto& 声明 = static_cast<const 变量声明&>(语句);
    llvm::Value* 值 = 生成表达式(*声明.初始值);

    // 如果有类型标注，验证类型一致性
    // （从符号表中获取变量声明时的类型标注，与实际值的类型比较）
    // 当前仅做基本检查：整数 vs 浮点 vs 字符串
    // 不匹配时发出警告而非错误（渐进式）

    符号表实例.声明变量(声明.变量名, 值);
    break;
}
```

**关键决策**: 第一步只发警告，不报错。这避免破坏现有程序。

**验证**:
1. `make 测试` 全部通过（无回归）
2. 手动测试类型不匹配时出现警告

### Task 4.2: 类型别名解析增强

**当前状态**: `类型别名映射` 在 `代码生成器` 中只做单层查找。

**修改文件**: `源/后端/代码生成器.cpp`

### Task 5.1: 循环导入检测

**修改文件**: `源/主程序.cpp`（导入处理部分）

当前导入逻辑在 `main()` 中，递归导入时无循环检测。

**方案**: 使用一个 `已导入集合` 跟踪正在导入的模块:
```cpp
std::unordered_set<std::string> 正在导入;
std::unordered_set<std::string> 已导入;

void 导入模块(const std::string& 模块路径, 程序& 主程序, const std::string& 输入目录) {
    std::string 规范路径 = 获取规范路径(模块路径);

    if (正在导入.count(规范路径)) {
        throw std::runtime_error("循环导入检测: " + 模块路径);
    }
    if (已导入.count(规范路径)) {
        return;  // 已导入，跳过
    }

    正在导入.insert(规范路径);
    // ... 解析和合并逻辑 ...
    正在导入.erase(规范路径);
    已导入.insert(规范路径);
}
```

### Task 5.2: 标准库搜索路径

**修改文件**: `源/主程序.cpp`

当前导入路径解析逻辑:
1. 相对路径（基于当前文件目录）
2. 添加 `.心` 后缀

需要添加:
3. 标准库路径（`标准库/` 目录）

```cpp
std::string 查找模块(const std::string& 模块名, const std::string& 输入目录) {
    std::vector<std::string> 候选;

    // 1. 相对路径
    if (!输入目录.empty()) {
        候选.push_back(输入目录 + 模块名);
        候选.push_back(输入目录 + 模块名 + ".心");
    }

    // 2. 标准库路径
    // 获取可执行文件所在目录
    std::string 程序目录 = 获取程序目录();
    候选.push_back(程序目录 + "标准库/" + 模块名);
    候选.push_back(程序目录 + "标准库/" + 模块名 + ".心");

    // 3. 绝对路径
    候选.push_back(模块名);
    候选.push_back(模块名 + ".心");

    for (const auto& 路径 : 候选) {
        if (文件存在(路径)) return 路径;
    }
    throw std::runtime_error("找不到模块: " + 模块名);
}
```
