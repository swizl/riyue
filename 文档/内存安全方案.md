# 日月 内存安全方案

> 目标：为日月补齐内存安全，消除越界/悬垂/脏读等不安全行为。
> 本文档给出**现状诊断 → 路线选择 → 分阶段调整清单 → 验证方法**，作为实施依据。
> 结论基于仓库实测源码证据。

---

## 一、内存安全的分类（要防什么）

| 类别 | 说明 |
|---|---|
| 空间安全 | 数组/切片越界读写 |
| 时间安全 | 悬垂指针、use-after-free、double free |
| 初始化安全 | 未初始化读 |
| 空指针安全 | 解引用空指针 |
| 类型安全 | 指针伪造、类型混淆 |
| 并发安全 | 数据竞争 |

---

## 二、现状诊断（证据）

| # | 现状 | 证据位置 |
|---|---|---|
| 1 | **无边界检查**：`arr[i]`、`x = arr[i]` 直接裸 `创建边界内GEP` | `源/后端/代码生成器_表达式.cpp` L1411-1430；`源/后端/代码生成器_语句.cpp` L270-295 |
| 2 | 仅运行时内建 `动态数组获取/设置/删除` 有 `0≤i<大小` 检查，且**静默返回 0** | `源/运行时/运行时辅助.c` L1887-1898 |
| 3 | **长度信息丢失**：动态数组在语言层是裸 `int*`；分片 `arr[1:3]` 只返回起始地址裸指针 | `源/后端/代码生成器_表达式.cpp` L1432-1442 |
| 4 | **无自动释放/无所有权**：90 处 `malloc/realloc/strdup`；`释放动态数组` 是**用户手动**内建，编译器**从不自动调用** | `源/共享/内置函数表.h` L139 |
| 5 | **GC 是「死」的**：`注册GC对象` 从未被 codegen 调用，`GC启用=0` | `源/后端/C运行时声明.h` L88；`源/运行时/运行时辅助.c` L2527-2531 |
| 6 | 局部变量**必带初值**（语法 `值 = 变量名`），局部未初始化读风险低 | `源/后端/代码生成器_语句.cpp` L183-198 |
| 7 | 自举侧镜像同样行为 | `自举/发射.心` L444；`自举/语法_树.心` L973-974 |

**结论**：当前模型 ≈ **C 风格裸指针 + 手动 malloc 且从不释放**。
- 时间安全：主要是**泄漏**（不 UB 但内存持续增长）。
- **空间安全：完全无防护（越界即 UB）**。
- GC：仅摆设。

## 三、路线对比

| 路线 | 做法 | 改动量 | 效果 | 取舍 |
|---|---|---|---|---|
| **A 运行时硬化** | 保留裸/手动模型，加边界检查 + 空检查 + 零初始化 + 启用 GC | 小 | 防越界/悬垂(GC)/脏读 | 有运行时开销 |
| **B 自动内存管理** | 真 GC 或 ARC，分配自动注册/回收 | 中 | 时间安全 + 无泄漏 | 需运行时改造 |
| **C 所有权 + 借用** | Rust 式编译期检查 | 大 | 全维度、零 GC | 需重构类型系统与前端 |

**推荐路径**：**A（已完成）→ C（主线）**；B/ARC 仅作**逃生舱**（`Rc`/`Arc` 式共享）。

> **目标调整（2026-10-12，用户决策）**：要「**和 Rust 一样安全**」，故主线走 **C**（所有权 + 借用检查，编译期证明、零 GC）；A 已作为运行时硬化地基完成；B 不再作为默认路线，仅保留为显式共享的逃生舱。

## 四、阶段 1：运行时硬化（具体调整清单）

> 原则：先做**代价低、收益高**的项，全部可通过回归验证。

### 4.1 运行时层（`源/运行时/运行时辅助.c`）
- [x] **堆对象零初始化**：`创建动态数组` / `创建动态字符串数组` / `创建通道函数` 的 `malloc` 改 `calloc`；增长路径 `realloc` 后 `memset` 清零新尾段，维持「容量内未写槽位恒为 0」（消除脏读）。
- [ ] **接上 GC**（可选）：把所有 `malloc/strdup` 出口改为 `注册GC对象(...)`；`main` 调 `启用GC()`；修复保守扫描（现仅扫 4096 个栈字、单表上限 1024，易漏/误判）。
- [x] 新增检查辅助：`运行时边界检查(索引, 长度, 位置)`、`运行时空检查(指针, 位置)`，失败即打印中文诊断并 `exit(1)`。
- [x] 内建 `动态数组获取/设置/删除/插入` 越界时**由静默返回 0 改为报错**（可开关：env `日月边界检查`，默认关；须用 `_wgetenv` 走 UTF-16，因 Windows 窄环境按 ANSI 码页编码，中文名与 UTF-8 字面量不匹配）。默认关的原因：自举编译器（`自举/解析器.心`）依赖 `动态数组获取` 越界返回 0 表达 EOF。

### 4.2 后端 IR 生成（`源/后端/代码生成器_表达式.cpp`、`_语句.cpp`；自举侧 `自举/发射.心`、`自举/语法_树.心`）
- [x] **局部定长数组**：索引/下标赋值处，编译期已知长度（`数组类型->getNumElements()`），插入 bounds check。**默认开**（用户决策）：新增运行时 `运行时数组越界陷阱(索引, 长度)`；宿主 `代码生成器::插入数组越界检查`（读 `_表达式.cpp`、写 `_语句.cpp`）、自举 `发射.心::发射越界检查`（读 `语法_树.心::发射下标访问`、写 `::发射下标写`）双链镜像——索引零扩展到 `整数64` 后 `无符号大于等于 长度` 即跳陷阱块调用中止，否则落穿继续。
- [x] **动态数组胖指针（语言层）**（用户决策：默认开）：动态数组在运行时结构已带长度（`动态数组={int* 数据; int 数组大小; int 容量}`、`动态字符串数组={const char** 数据; int 数组大小; int 容量}`），语言层 `arr[i]` / `arr[i]=值` 此前不经长度检查。现新增**恒开启**运行时入口 `动态数组索引获取/设置`、`动态字符串数组索引获取/设置`（越界即 `运行时越界报告` 并 `exit(1)`，与内建 `动态数组获取/设置` 默认返回 0 以兼容自举解析器 EOF 语义不同）；双链镜像——自举借用独立表达式类型 `动态数组`/`动态字符串数组`（局部类型码 `D`/`E` → 查类型 `10`/`11`），宿主 `符号表::设置动态数组变量/是动态数组/获取动态数组元素` 登记元素种类，`下标访问`（`_表达式.cpp`）与 `下标赋值语句`（`_语句.cpp`）命中即改走上述入口。
- [x] **字符串胖指针（选项 2 落地，默认开）**：`字串` 在语言层是**指向 `{ 数据, 长度 }` 的指针**。自举链新增 `发射字符串结构常量表`（字面量入 `私有 常量 { 指针, 整数32 }`）与运行时助手 `胖字符串包装/数据/长度/字符码/拼接/子串/取字符/转整数/比较`；在「内建/运行时 C」边界按需**包装**（结果为 `字符串` 且非「已是胖指针」的调用）与**解包**（传给非用户函数的实参），使语言层胖字符串与运行时 `const char*` 互通。宿主种子链维持裸 `char*`（语义等价——仅需支撑自举，不参与不动点文本比对）。
- [x] **语言级「指针」类型（不透明句柄，默认开）**：新增局部码 `P`（`查类型`=12、`查函数返回类型`=4、`类型转IR`/`输出码转IR`/`输出码到表达式类型`=`指针`），把自举与 peg 中**实为运行时句柄**（动态/动态字符串数组、CST 子列表、`元数据行`、`当前函数局部号表`、`令牌*` 数组）却写作 `:字符串` 的声明改标 `:指针`；`发射` 全链（存储/加载/返回/普通调用/形参复制/局部与全局声明）双链镜像支持。**根因**：包装/解包按静态类型 `字符串` 触发，而裸句柄与真字符串共用 `字符串` 类型即被误包装/误解包（二次自举 `二级.exe` 堆损坏 `STATUS_HEAP_CORRUPTION`）；类型分离后消除误判。
- [x] **通道句柄类型纠正**：`创建通道` 结果由 `字符串` 改 `指针`（通道句柄是运行时结构体指针，非字符串），消除其被误包装/解包的段错误。
- [x] **分片返回胖指针**（带长度），不再返回裸偏移：`arr[起:止] / [起:] / [:止] / [:]` 现返回运行时胖切片 `{数据, 长度}`（自举 `切片创建/切片数据/切片长度/切片取整数/切片取指针`）；切片下标读改走带长度检查的运行时入口（越界即中止）。宿主与自举双链镜像。
- [x] **动态数组分片长度取自运行期**：`动态数组[i:j]` 此前不可用——`分片访问` 的元素基址与长度按变量静态类型取（`符号表::获取数组大小` 仅定长数组有值 → 动态数组得 `0`；且把动态数组**句柄**当数据指针 `GEP`），宿主链运行期越界中止、自举链产出非法 IR。修法：把「取长度 / 取数据基址 / 越界 / 构造切片」收敛到**运行时助手** `动态数组分片` / `动态字符串数组分片`（`止 < 0` 视作「到末尾」，越界即 `运行时越界报告`，内部复用 `切片创建`），双链 codegen 仅对 `是动态数组(名)` 发一次调用；定长数组路径不变。详见 §8.5 `S1`。
- [x] **解引用前空检查**（成员访问/方法调用/映射取值）：新增运行时 `运行时空检查(指针, 位置)`（空则打印「运行时空指针: <位置>」并 `exit(1)`）。**双链镜像**——宿主新增 `解析并检查解引用指针`（栈槽且分配类型为指针 → 加载出句柄后检查；本身即句柄值 → 直接检查；栈上结构体值 / 全局存储地址恒非空 → 跳过），插入 `查找结构体成员地址`（成员访问/成员赋值）、成员赋值调用点、映射取值、方法调用接收者四处；自举新增 `发射空检查`，插入 `发射成员访问` / `发射成员调用` / `发射下标访问`（映射分支）三处。**两链表示差异**：自举的结构体/映射变量是**指针句柄**（可被置空，检查可真实触发），宿主为**栈上的结构体值 / 全局存储地址**（恒非空，检查近乎不可达）——故运行时中止证据只在自举链可获得。
- [x] **堆分配 calloc 语义清零**：见 §4.1 首项（`malloc→calloc` + 增长路径 `memset` 清尾），已于 2026-10-12 完成。

### 4.3 阶段 A：三形态类型语法 + 视图不可逃逸（已完成 S1–S6）

> **目标**：把「长度 / 所有权」带进**类型**，作为后续 move / drop / 借用检查（路线 C）的地基。
> **用户决策**：只保留三种**后缀**形式；切片本身即视图。

#### A.1 语法（`工具/日月/日月.文法`）

```
类型     = 基本类型 数组后缀?
基本类型 = '整数' / '浮点' / '布尔' / '字符串' / '函数' / '空' / 标识符
数组后缀 = '[' 数字 ']'   // T[N] 定长
         / '[' ']'        // T[]  动态
         / '[' ':' ']'    // T[:] 切片
```

| 形式 | 含义 | 归一化叶文本 |
|---|---|---|
| `T[N]` | 定长数组：内联、栈上 alloca、不可增长 | `整数[3]` |
| `T[]` | 动态数组：堆手柄 `{数据,大小,容量}`、**拥有**、可增长 | `整数[]` |
| `T[:]` | 切片：胖指针 `{数据,长度}`、**不拥有、不可增长、即视图** | `整数[:]` |

- **删除**上一会话的前缀 `切片[T]`：文法 `切片类型` 规则（`工具/日月/日月.文法` L64-65）与宿主前缀匹配（`源/后端/代码生成器.cpp` L133、L300）。
- **并入** `数组标记`（`[]`，原仅 `类型别名` 用，见 L43-44）：消除「类型别名才认 `[]`」的双轨。
- 标注**可选**（现状无标注的代码继续合法，90 个回归不受影响）。

#### A.2 下标按类型推理（`a[i]` / `a[i] = v`）

| `a` 的静态类型 | 分派入口 | 越界检查 |
|---|---|---|
| `T[N]` | 内联 alloca → GEP | 编译期 N + 运行时陷阱（已有） |
| `T[]` | `动态数组索引获取/设置` | 恒开启（已有） |
| `T[:]` | `切片取整数` / `切片取指针` | 恒开启（已有） |
| `映射` | 映射取值 + 空检查 | — |
| `文本`/`字符串`（标量） | `字符串字符码检查`（宿主裸 `char*`）/ `胖字符串字符码检查`（自举胖串） | 恒开启（`文本[i]` → `文字`；见 **A.9**） |

- **新要求（用户指令）**：元素码由 `T` **推理**得出，不再运行时写死 —— `动态数组`(码10) 与 `动态字符串数组`(码11) **合并为一类**，元素类型由**数组字面量 / 类型注解**推断。

#### A.3 视图不可逃逸（`T[:]` = 视图）

定义：`T[:]` 的生命周期**不得超出产生它的函数帧**。

- **允许**：形参传入、局部临时、立即下标 / 长度读取、再分片、作实参向下传递（重借用）。
- **禁止**（4 类跨界位置）：
  1. 作**返回值**（返回类型含 `[:]`、或 `返回 <视图表达式>`）；
  2. 作**结构体成员**类型；
  3. 作**全局变量**类型；
  4. 存入**动态数组 / 映射**（堆容器）。

> **取舍说明**：现实现把分片结果登记为「切片变量」（宿主 `设置切片变量`、自举 `切片表`）——落**局部**变量槽不属逃逸，故保留；只拦上述 4 类跨界。

#### A.7 新增 `文字` 类型（Rust 式：单 Unicode 码点，i32）✅

> **命名**：本类型初名 `字符`，因与 `字符串` 视觉重叠、易致 `字符串[]` 被误读为 `字符[]`（见 A.8），已改名 **`文字`**。

- **定位**：`文字` = 单个 Unicode 码点，IR 表示 `整数32`；与 `字符串`（UTF-8 胖指针 `{数据,长度}`）不同。`文字[]` = 码点动态数组（区别于 `字符串[]`）。
- **文法/词法**：无需改动 —— `文字` 与 `指针` 同路（走 `标识符` 类型名，非关键字；内置 `字符(码点)` 因此不受影响，无需改名）。
- **宿主链**：`类型名到LLVM类型` `文字`→`整型32`；字符字面量已由 `字符表达式`→i32 常量支持；`打印` 分支经 `是文字值表达式` 判定后走 `@字符序列`→`%s`（与自举链一致）。
- **自举链**：`类型名到局部码` `文字`→`R`、`类型名到IR` `文字`→`整数32`；`查类型` `R`→24；`类型转IR` `文字`→`整数32`；`数组对齐` `R`→4；`发射变量`(码24)→加载 `整数32`/表达式类型 `文字`；局部声明 `目标码 R`→登记 `R`/存储 `整数32`；参数经 `类型名到IR`→`整数32`、登记码 `R`；返回类型码 `R` 登记 + `查函数返回类型` `R`→24 + `发射普通调用` 码24→`整数32` 调用/表达式类型 `文字`；新增 `发射叶字符`（`'x'`→码点常量，`种="字符"/"字符字面"` 双入口）；`打印` 新增 `文字` 分支（`@字符序列(码点)`→`%s`）。
- **验证**：探针 `阶段/字符冒烟.心`（标量 + 多字节码点 + `文字[]`/`字符串[]`/`文本[]` 元素码推理）→ 输出 `A/字/X/Y/Z/好/上/下/左`；回归 **87/0**；不动点一致（4,283,113 字节，SHA256 `48ba57bc…`）。

#### A.8 字符串类型首选写法 `文本` + 命名收窄 ✅

- **动机**：`字符串[]` 可能被读成「字符串里的字符」（即 `文字[]`）—— 主因是 `字符串` 本身含 `字符` 子串，中文分词视觉重叠。
- **决策**：
  1. 引入 **`文本`** 作为字符串类型的首选写法（`文本` ≡ `字符串`，二者同码 `S`；`字符串` 保留兼容旧代码）。`文本[]` 只可能是「文本的数组」，字面零歧义。
  2. rune 类型 **`字符` → `文字`**（避开与 `字符串` 的子串重叠）。
  3. **收窄 `文字`**：定位为「索引 / 遍历的产出类型」，字符串操作一律走 `文本`/`字符串`；`文本[i]` 产出 `文字`。
- **实现**：`文本`/`文字` 均走 `标识符` 类型名（无文法改动）。宿主 `类型名到LLVM类型`（`文本`→指针、`文字`→整型32）、自举 `类型名到局部码`/`类型名到IR`/`类型转IR` 各增一条。
- **验证**：同 A.7。

#### A.9 字符串下标带界检查（`文本[i]` → `文字`）✅

- **目标**：闭合 §4.3 A.2 记录的缺口——标量字符串下标 `文本[i]` 此前两链均落**裸指针回退分支**（宿主 `源/后端/代码生成器_表达式.cpp` L1637 裸 `i32` GEP；自举 `自举/语法_树.心` 空分支原样放行、把整串其后的下标表达式忽略），既非 UTF-8 字符级、也无长度检查（越界 = UB）。现按 §4.3 A.8「`文本[i]` 产出 `文字`」语义接线为**运行时带界入口**。

### 8.0 反向赋值语义前提（实现必读）

日月 `左 = 右;` 表示 **右 := 左**（值在 `=` 左边）：
- 解析分两支：`赋值语句 = 表达式 类型标注? '=' 目标 ';'`（左为非标识符/复合表达式 → **反式**，`目标` 在右）；`标识符赋值 = 标识符 目标尾`（左为裸标识符 → 常规，标识符即目标）。
- 于是 `A = B;`（两侧均裸标识符）恒走**反式**：源 = `A`（左），目标 = `B`（右）→ 语义 `B := A`，**移动的是左值 A**。
- 宿主链：`A = B;` 生成 `变量声明(变量名=B, 初始值=A)`（非标识符侧的 `x = <非标识符>;` 才落到 `赋值语句`）。故移动判定落在 **`变量声明` 分支**（源=`初始值表达式`）与 **`赋值语句` 分支**（源=`值表达式`、目标含 `.` 时跳过）。
- 自举链：`发射赋值` 的**反式路径**（`发射赋值到目标`，源 = `赋值甲` = 子 0）承载移动；`标识符赋值` 的裸值形式（`x = <非标识符>;`）源必非裸变量，天然无移动。

  - **不释放——O2b 剩余项闭合结论（2026-10-13，经双链代码侦察）**：
    - `映射`：**非堆分配**，故无「释放」可言。两链 `映射` 字面量均发射为**模块级静态全局** `@.映射N = 内部 全局 %映射类型 零初始化`，`%映射类型 = { [1024 x 指针], [1024 x 指针] }`（宿主 `代码生成器_表达式.cpp`「`情况 表达式类型::映射字面量`」段；自举 `语法_树.心` `发射映射字面`）。全程无 `malloc`/`free`，重绑定仅改指向的全局句柄。→ **撤销**原注记「运行时无 `释放映射` 入口（留待 O2b 补）」：这不是遗漏，而是**本就不需要**；若补 `释放映射` 对静态存储 `free` 反而为 UB。
    - 含拥有型字段的结构体：**保守泄漏**（不逐成员释放）。理由：结构体成员不可能为 `映射`，拥有型字段仅来自 `T[]`/嵌套拥有型结构体；而 **O1b-2 侦察确认无任何既有示例 / 自举源码使用拥有型字段结构体**，且未释放仅**泄漏**（非安全问题，与既有「保守泄漏」口径一致），实现须同时改宿主 + 自举的成员遍历释放路径、风险高于收益，故**明记不实现**。
    - `指针` 句柄：保持排除（自举节点池 / 结果变量大量以 `指针` 承载句柄，不可释放）。

**O1b-1 前置修正（双链镜像）**：宿主链映射变量此前为「符号直接映射句柄（不经 alloca）」，而自举链为「alloca + load」；当映射变量作**值表达式**使用（如反式 `原图 = 别名;`）时，宿主链落入 `表达式类型::变量` 的 `GlobalVariable` 分支误加载整段映射结构体 → **段错误**。修法：`表达式类型::变量` 对 `是映射变量` 直接归返句柄（与数组同处理），并在 `变量声明` 增「源为映射变量」分支（句柄直接映射 + `设置映射变量`，引用语义）。

### 8.2 规则

1. **移动**：赋值（含反式声明）**源侧恰为裸变量引用**且该变量为拥有型 → 该变量标记**「已移动」**。
2. **复位**：赋值/声明的**目标变量**被重新绑定 → 清除其「已移动」。
3. **使用即错**：读取**已移动**变量 → 编译错误 `使用已移动的值: <名>`，并置 `未声明出错` 中止（自举）/ 抛 `运行时异常`（宿主）。
4. **越过边界不移动**：传参、返回按既有「按指针 / 视图（借用）」约定**不移动**（与 Rust 的差异，明记）。
5. **自动 Drop（O2）**：函数体内**新建**的拥有型（动态数组）局部变量，在其**唯一退出点**（`返回` 被禁 → 函数末尾自动返回前）插入释放调用：元素码 `2`（`字符串[]`/`文本[]`）→ `释放动态字符串数组`，否则（码 `1`/`3`）→ `释放动态数组`。
   - **不自动释放**：全局变量、形参、返回值变量、**已移动**变量、**逃逸**变量。逐条对应规则 1/4 的语义（移动=所有权转移；返回/传参不改所有权，但一旦句柄可能被外部持有即判逃逸）。
   - **逃逸判定（保守）**：局部拥有型变量的**名称**若出现于下列任一位置，则判逃逸、**不**释放（保留泄漏，换取不悬垂）：
     (a) 作为**实参传给用户自定义函数**（含成员方法调用）；
     (b) 作为**结构体字面量的字段值**（含拥有型字段，§8.1 O1b-2）；
     (c) 作为**结构体成员赋值**的源（目标名含 `.`）。
   - **原因**：规则 4 使「传参/返回」不改所有权，句柄仍归本函数；若外部（被调函数 / 结构体 / 全局）可能长期持有该句柄，函数退出释放即悬垂。故一律排除这些路径。
   - **本步不含**：覆盖（重绑定）时释放旧值（**已由 O2c 补齐，见 §8.8**）、`映射`/拥有型结构体成员释放——留待 O2b 其余项（**已闭合，见 §8.1「不释放——O2b 剩余项闭合结论」**）。
6. **块级提前释放（O2b）**：函数体内**任意代码块**（函数体顶层 / 嵌套块 / 循环体 / `如果` 分支）中**新建**的拥有型（动态数组）局部变量，在其**所属代码块退出时**（而非函数末尾）插入释放调用——即在作用域/块深度处发射 `释放动态数组`/`释放动态字符串数组`。
   - **同深度配对**：声明与其释放落在**同一块深度**，故释放的执行次数与该块被执行的次数一致（循环体每轮释放；`如果` 分支仅在该分支执行时释放）。
   - **块被终结时**（块末指令已为 `返回`/`中断`/`继续` 等终结指令、无法再发射）：跳过释放并**移除**该登记项（保守泄漏，换取不悬垂；避免对未初始化句柄释放或跨层误释放）。
   - **不自动释放**：同规则 5（全局 / 形参 / 返回值变量 / 已移动 / 逃逸）。**函数体顶层块**的释放：宿主链由「自动返回前」显式调用 `发射释放当前作用域()` 完成（自动返回会终结该块，作用域退出钩子届时无法再发射），自举链由函数体 `发射代码块` 的块出口完成（其退出早于自动返回）。块级释放通过**退出作用域钩子**（宿主）/ `发射代码块` 出口（自举）统一挂接，避免逐个改造 `作用域守卫` 调用点。
   - **本步不含**：覆盖（重绑定）时释放旧值（**已由 O2c 补齐，见 §8.8**）、`映射`/拥有型结构体成员释放、指针句柄——留待 O2b 其余项（**已闭合，见 §8.1「不释放——O2b 剩余项闭合结论」**）。
7. **借用规则（O3，暂无前缀标注、纯静态、保守）**：切片视图 `T[:]` 是**只读借用**；在其存活期内，禁止对**源容器**做「会改变存储 / 转移所有权」的操作。
   - **别名登记**：局部变量 `v` 由**分片创建**产生（`v = a[起:止]` 声明、或 `T[:]` 注解 + 分片初始化，如 `a[1:3] = v:整数[:];`）→ 登记「视图 `v` 只读借用源 `a`」，并记其**声明块深度**（**按视图名**登记两个映射：`视图名 → 源名`、`视图名 → 块深度`；同名视图再次登记即覆盖旧绑定）。
   - **存活期（O3-2c2 精确 NLL）**：取「**视图末次使用所在语句**」——借用存活至视图**最后一次被使用**的那条语句（该语句本身仍在借用期内，故该语句内的改源仍报错）。若末次使用位于某循环体内，则取**最外层循环语句**为释放点（循环体会重复执行该使用，借用须存活至该循环退出）；若视图**从未被使用**，则借用**立即结束**（NLL：不再产生假阳性）。**保留「声明所在代码块退出」作兜底**（末次使用点晚于/不落在块出口时，仍由块退出释放）。
   - **NLL 判定口径**：预扫描函数体，**读位置出现视图名即记一次使用**；**赋值目标不计使用**（`赋值语句.变量名` 为写方、非读方；重绑定语义见 O3-2b）；**匿名函数体内**的使用记「永不释放」（保守：闭包可被延迟调用，闭包对借用源的使用不受本帧末次使用点约束）。
   - **禁改源**：存在对 `a` 的借用期间，对 `a` 执行下列之一即报错（`未声明出错` 中止 / 抛 `运行时异常`）：
     (a) **下标写** `a[i] = x;` → `借用期内不可修改源: a`；
     (b) **移动** `a`（`a` 作反式赋值源、且为拥有型）→ `借用期内不可移动源: a`；
     (c) **改源内建**（O3-2a，会改变存储 / 转移所有权，`realloc` 使视图失效）：`a` 作**首实参**传给 `动态数组添加` / `动态数组插入` / `动态数组删除` / `动态数组设置` / `释放动态数组` / `动态字符串数组添加` / `动态字符串数组插入` / `动态字符串数组删除` / `动态字符串数组设置` → `借用期内不可修改源: a`。
     (d) **经视图写**（O3-2c1，视图为只读借用）：以切片视图为**下标写目标**（`x = 视[i];`，反式即 `视[i] := x`）→ `不可写入只读视图: 视`（写入等于改其借用源的存储，破坏只读借用；亦为 `视` 不可变类型约束）。
   - **解除**：(i) **重绑定即解除（O3-2b）**——视图名 `v` 或借用源名 `a` 作赋值**目标**被重新绑定 → 立即解除相应借用（见下一 bullet）；(ii) **（O3-2c2）末次使用所在语句发射后** → 解除该视图借用（视图从未使用时，于声明语句发射后即解除）；(iii) 声明借用的代码块退出 → 删除该视图的借用登记（按块深度裁剪，与 O2b 同机制，作兜底）。
   - **重绑定即解除（O3-2b）**：
     - **视图名重绑定**：视图 `v` 作赋值目标被改绑（如 `乙[0:1] = v:整数[:];` 或 `5 = v;`）→ **先**解除 `v` 原有的借用；若改绑到新分片再按「别名登记」登记新借用（新源进入借用期）。
     - **重绑定源**：借用源 `a` 作赋值目标被重新绑定（如 `()创建动态数组 = a;`）→ 解除以 `a` 为源的**全部**借用。依据：重绑定后 `a` 指向新容器，原视图所指旧存储不再经 `a` 可达（覆盖不释放旧值 → 旧存储泄漏但**不悬垂**）。
   - **O3-2 增量**：O3-2a **改源内建**（见上 (c)）；O3-2b **重绑定即解除借用**；O3-2c1 **写路径禁改源**（见上 (d) 经视图写；**成员写**受文法限制不可触发，见边界）；O3-2c2 **精确 NLL 存活期**（借用随视图**末次使用**结束，取代「块退出」，消除假阳性）；O3-2c3 **可变借用数量约束**（待「可变借用」概念引入；当前语言切片视图**恒为只读**，无「可变借用」可约束，故暂无对象）。
   - **边界（明记）**：`字符串`/`文本` 为引用语义不可变 Copy、非容器，不参与借用登记；视图作为形参向下传递（重借用）不改变本帧登记。**成员写对「借用源」不可触发**：分片源 `数组名` 必为裸标识符（文法 `标识符 '[' ... ']'`），`对象.成员[i:j]` 不可解析，且结构体不可切片 → 不存在「以成员为源的借用」，故 (d) 仅覆盖经**视图**写。

### 8.6 O4a 生命周期省略（视图可返回）方案

**目标**：解除「视图完全不可逃逸」硬约束中**返回值**一类，允许函数返回**其唯一数组类形参的切片**（如 `取前段`），同时保持内存安全（不悬垂、借用存续期内禁改源）。

**省略规则（elision）**：函数 `f` 的返回值含切片视图 `U[:]` 时，

1. `f` 须**恰有一个数组类形参 `p`**（类型名含 `[`：`T[N]` / `T[]` / `T[:]`）；多于或少于一个 → 报错 `视图不可逃逸: 函数 'f' 返回切片视图 'U[:]'，须恰有一个数组类形参且视图须由其派生`。
2. 返回视图的生命周期**绑定到 `p`**（语义等价 `fn f<'a,…>(p: &'a [U]) -> &'a [U]`）。

**定义侧溯源检查**：函数体中对**结果视图变量**的每次赋值，值须为「基为 `p` 的分片」（`p[...]` / `p[i:j]` / `p[:]`）；否则报错（防止返回**本帧局部**的切片 → 悬垂）。当前仅支持 `p` 的分片形式（`p = 结果;` 原样转发暂不支持，留待 O4b）。

**调用点借用登记**：调用 `f(...)` 的返回值存入变量 `w` 时（`f(...) = w;`），登记 `w` **只读借用** `f` 第 `p` 位置的实参；实参须为**裸标识符**（可溯源容器），否则保守报错。`w` 存活期内（NLL，随 `w` 末次使用结束）禁对其实参改源（下标写 / 移动 / 改源内建）。

### 8.7 O4b 生命周期显式标注（视图可返回·多数组形参）方案

**目标**：解除 O4a「恰有一个数组类形参」的限制 —— 当函数有**多个**数组类形参且返回视图时，用**显式标注**指明结果视图的生命周期绑定哪个形参。

**语法（对计划原案的偏离，明记理由）**：计划原写 `&'a` 形式（Rust 风格），但 `'` 在本语言词法中为**字符字面**起始符（`%token 字符字面 '[^']*'`），`&'a` 会与之冲突；故改用 **`&形参名`**（复用既有 `&`（`标记类型::位与`）标记，**无需新词法**）。形式为返回值输出参数的**前缀**标注：

    函数 (甲:整数[], 乙:整数[])取首(&甲 结果:整数[:]) { 甲[0:2] = 结果; }

**语义**：`&p` 显式指定结果视图的生命周期绑定形参 `p`（即 O4a 省略规则本应推断出的那个形参）。约束同 O4a：`p` 须为该函数的**形参**且为**数组类**（类型名含 `[`），否则报错；定义侧溯源检查、调用点借用登记（绑定到 `p`）**完整沿用 O4a**，不新增。

### 8.8 O2c 覆盖（重绑定）时释放旧值方案

**目标**：补齐 O2/O2b 明记的「覆盖（重绑定）时释放旧值」——对**已登记待释放**（本函数新建的拥有型动态数组局部）的变量作**重绑定**（该名作赋值目标、非成员/下标目标）时，在**覆盖前**释放其旧句柄，消除「重绑定泄漏旧容器」的缺陷。

**侦察结论（两探针实测）**：`阶段/_o2c_侦察.心` 重绑定 `甲` 后自举 IR **仅**在函数出口释放一次（`%tmp1` 旧数组泄漏、只释放末次句柄）；`阶段/_o2c_侦察2.心` 嵌套块内重绑定**不**在块出口释放、**不**改变释放点深度（旧登记深度保持）。即当前双链行为一致：重绑定既不释放旧值、也不动登记深度。

**语义**：
1. 覆盖前，若该名 ∈ 待释放（本函数新建拥有型动态数组局部）且**未移动、未逃逸** → 发射释放旧句柄（`释放动态数组`/`释放动态字符串数组`，按登记元素码）；已移动/逃逸者不释放（所有权已转移 / 句柄可能被外部持有），但后续登记处理同下。
2. 覆盖后，若新值**非**拥有型（非动态数组 / 为切片 / 标量）→ 从待释放**移除**该名（避免块出口对非拥有型误释放）；（自举链另需清 `待释放深度表`）。
3. 覆盖后，若新值**仍为**拥有型动态数组 → **保持原登记不变**（释放点仍为首次声明所在块；不重登记，避免嵌套块内重绑定把释放点下移到内层块 → 提前释放/悬垂）。
4. **不新增**「非拥有型局部重绑定为拥有型」的自动登记（与既有「仅新建时登记」口径一致，保守泄漏、非新增缺陷）。

**两处自举链关键陷阱（验证时发现并修复）**：① `发射值存储` 顶部 `(已移动表, 目标名)文本表删;` 先于释放检查执行 → 移出的源会被误释放（双重释放）；故 `重绑已移` 须在**其之前**捕获。② `重绑曾待释放` 若在「新建登记」（`待释放表` 写入）**之后**取，则首次声明也会命中 → 对未初始化句柄释放（段错误）；故须在登记**之前**捕获。③ `重绑新拥有` 须用**整数**标记（`0 = …`），初值写 `""`（空串）会使 `?= 0` 恒假、非拥有型无法移除登记（释放点误留在块/函数出口）。

**为何重绑定处「保持原登记」即可**：两链登记均在**首次声明**处发生（宿主 `本次新建` / 自举 `类型码 ?= 0`），重绑定路径**不再**触发登记（自举 L2858 段 `目标码` 对既有变量为陈旧值、通常不命中 `D`/`E`），故既有的原始深度登记天然保留，无需重登记与深度搬运。

**探针（双链一致）**

1. `阶段/覆盖释放合法.心`（正例）：`()创建动态数组 = 甲;` 填充 → `()创建动态数组 = 甲;` 重绑定填充 → 读取输出；两链 IR 在**重绑定存储之前**含一次 `释放动态数组`（旧句柄）+ 函数出口一次（新句柄），运行输出不变。
2. `阶段/覆盖释放_切片.心`（正例）：拥有型 `甲` 重绑定为切片视图 `乙[0:1] = 甲;` 后读取 `甲`；两链 IR 含旧值释放、且**块出口不再**对 `甲` 释放（非拥有型）；运行输出不变。
3. `阶段/覆盖释放_负.心`（负例·已移动）：`乙 = 甲;`（移动）后再 `()创建动态数组 = 甲;` 重绑定；两链**不**对旧值重复释放（`已移动` 跳过），运行输出正确。

### 8.9 O3-2c3 可变借用（可变切片视图 + 数量约束）方案

**目标**：引入「可变借用」——**可写入**的切片视图 `T[可变:]`，并实现借用数量约束（O3-2c3）：对同一源容器，**可变借用独占**（至多一个可变视图，且不得与任何只读视图共存）；只读借用之间可多个共存（现状不变）。以此闭合 O3 借用规则链（原 `O3-2c3` **曾**因「当前切片视图恒只读、暂无对象」而阻塞，本步引入可变视图后解除）。

**语法**：扩展数组后缀，新增第四种 `T[可变:]`（归一化叶文本后缀 `"[可变:]"` → 类型叶文本如 `整数[可变:]`）。
- 与 `T[N]`/`T[]`/`T[:]` 并列；`可变` **仅**在此位置作关键字（文法内联字面量，非全局保留字）。
- 视图判定扩展：类型名含 `"[:]"` **或** `"[可变:]"` 即为视图（沿用「视图不可逃逸」全部约束）。
- 语义：`整数[可变:]` 为**可写**切片视图；`整数[:]` 仍为只读。

**语义**：
1. **可变视图写入**：`视[i] := x`（反式 `x = 视[i]`）在 `视` 为可变视图时**放行**，直达源容器存储（经新增运行时入口 `切片设置整数`/`切片设置指针`，越界即中止）；`视` 为只读视图时仍报错（O3-2c1 不变）。
2. **借用可变性**：登记借用时增记「视图是否可变」。`T[可变:]` 注解 + 分片初始化 → 登记**可变**借用；`T[:]` → 只读借用（现状）。
3. **数量约束（O3-2c3）**：登记借用前检查——① 登记**可变**借用时，若源已有**任何**借用（只读或可变）→ 报错 `可变借用冲突: 源 '甲' 已被借用`；② 登记**只读**借用时，若源已有**可变**借用 → 报错 `可变借用冲突: 源 '甲' 已被可变视图借用`。只读借用之间不冲突（多读者允许）。
4. **独占写（不变）**：源 `甲` 处于（可变或只读）借用期时，`甲` 作下标写目标 / 移动源 / 改源内建首实参 → 仍报错（既有 O3/O3-2a 检查不变）；可变视图的写入**只**经视图名 `视` 进行。
5. **边界（明记）**：可变视图不参与 O4a/O4b 视图返回（返回路径只处理只读 `[:]`；可变视图不可逃逸同 §4.3）；可变视图与只读视图共享同一「借用登记 + NLL 解除」机制，仅多记一个可变标志。

### 8.10 O4a 遗留局限收尾：视图返回结果作实参的保守收窄方案

**背景（§8.6 已知局限）**：O4a/O4b 的调用点借用登记**仅**在「视图返回调用结果**绑定到变量**」（`f(...) = w;`）时发生；结果**内联使用**（不绑定变量）时不登记借用，保守不设防。

**语法现实（双链核查，先纠正前提）**：宿主手写解析器仅支持**裸标识符**作下标/分片基（`源/前端/语法分析器.cpp` L393 `如果 (当前.类型 == 标记类型::标识符)`；括号函数调用在 L380-385 解析后**直接归返、不接后缀**），故 `(call)[0]` 形式在宿主链**无法解析**。又因自举链始终以 `引导.exe`（宿主解析器）编译自举源码，该形式**两链均不可用**。⇒ 实际可用语法中，「内联使用」**恒等价于「作实参」**（把视图返回调用结果直接作为某函数的实参）。

**可利用性分析（按被调类别）**：
1. **作实参 · 内置函数**（`((甲)取前段)长度;`）：内置函数不持有、不改源 → 安全，**放行**。
2. **作实参 · 用户自定义函数**（`((甲)取前段)处理;`）：视图实参生命周期随语句终止、**不可跨函数追踪**；若被调同时持有源容器并对源增长/移动，则实参视图指向已释放的旧缓冲（潜在 UAF）。→ **采纳保守收窄**。
3. **链式返回**（把内联视图作视图返回函数 `g` 的数组实参）：已被 O4a/O4b 既有「实参须为**裸标识符**」检查拒绝（抛 `视图返回: 实参须为可溯源容器（裸变量）`），无需重复处理。

**为何不采纳「语句作用域合成借用」**：曾考虑在调用求值点为视图返回调用登记一个「合成视图名」的只读借用（合成名不入 NLL 末次使用表 → 语句结束即自动解借）。但 NLL 为**语句粒度**，该机制对「同一语句内先读视图、后改源」的合法代码（如 `(甲, ((甲)取前段[0]))动态数组添加;`，视图元素在增长**之前**即已读出）会产生**假阳性**，与「护栏优先（回归 90/0）」相悖；且如上所述宿主链根本无法解析该形式、无实际触发面。故**不采纳**（避免过度保守与过度设计）。

**规则（新）**：**视图返回调用的结果不得作为用户自定义函数的实参** → 报错 `视图不可作为实参传递: 视图生命周期无法跨函数追踪`。绑定到变量的路径**不变**（沿用 §8.6 借用登记）；内置函数实参放行。

**双链落点**

| 链 | 文件 | 落点 |

| 宿主 | `源/后端/代码生成器_表达式.cpp` | `情况 表达式类型::函数调用` 的**用户自定义函数段**（`函数定义` 确定后、实参求值前）：扫描 `调用.参数列表`，任一实参 `类型 == 表达式类型::函数调用` 且其 `函数名 ∈ 视图返回形参` → 抛 `运行时异常` |
| 自举 | `自举/语法_树.心` | `发射调用` 函数体顶部、`用户函数命中 ?= 1` 分支（与既有「改源内建」「逃逸标记」检查同区块）：扫描调用节点实参子 `(节点,i)取子`，任一 `取种类 == "函数调用"` 且其名 ∈ `函数返回表` 且返回码 `== "L"` → `借用报错` |
