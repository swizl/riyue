# S3 日月文法 计划

> 目标：用 S2 的 PEG 内核，为 日月 语言本身编写完整文法（词法 + 文法），并支持**类型化节点 + 语义动作**，最终可解析全部 `示例/*.心` 并与宿主前端结果对比。
> 路线图见 docs/superpowers/specs/2026-09-29-peg-parser-design.md §9/§11。

## 用户决策（本阶段启动时确认）

1. **首个里程碑 = 直接类型化节点 + 语义动作**（不对接通用 CST 中间态）。
2. **现在就扩展 PEG 内核**：支持 `名:e` 具名子节点 与 `{ … }` 语义动作。（含解释模式内建求值——见「风险」。）

## 风险与务实取舍（重要）

- 解释模式执行 `{ … }` 动作需要「日月 代码求值器」（等价于写 日月 解释器），成本极高。
- 务实路径：**动作执行先只在 生成模式 落地**——生成器把动作原样嵌入生成的 日月 解析器，由 日月 编译器原生编译执行（拥有全部语言能力）。
- 解释模式先做到：解析 `名:e` 与 `{ … }` 语法、在 CST 上**附加命名子节点与动作源文本**（不执行动作）。
- 解释模式真正求值动作，作为独立的后续子步（S3.5，可选/延后）。本计划先交付 1-4。

## 现状（S2 产物，均已提交并推送）

- 工具/peg/词法.心：正则子集匹配器，`正则匹配(文本,模式,起始)`。
- 工具/peg/文法.心：`%token/%keyword/%skip` + 规则表（`名:表达式原文本`），入口 `解析文法`。
- 工具/peg/匹配.心：分词 + 通用 CST（规则名 + 子节点 + 文本），入口 `识别(文法,输入)`。**不支持 `名:e`、`{…}`**。
- 工具/peg/生成.心：PEG → 日月 递归下降解析器源码，入口 `生成解析器(文法,输出)`。**不支持 `名:e`、`{…}`**。
- 工具/peg/主程序.心：CLI `识别 文法 输入` / `生成 文法 输出.心`。
- 玩具文法验证：`1+2*3` → `(程序 (加减 (乘除 (原子 1)) + (乘除 (原子 2) * (原子 3))))`，host==boot。

## 任务切分

- **S3.1 内核加 `名:e` 标签**（匹配.心 + 生成.心）：CST 节点可命名子节点；生成代码把命名子节点绑定到局部变量 `名`。
- **S3.2 内核加 `{ … }` 动作**：文法解析器识别动作；匹配.心 CST 附加动作文本；生成.心 把动作**原样嵌入**生成的解析函数（放在对应序列项之后）。
- **S3.3 日月词法规则**：`%token`（整数/浮点/字符串/字符/标识符/符号）、`%keyword`（保留字）、`%skip`（空白/行注释/块注释）。
- **S3.4 日月文法规则**：按 源/前端/抽象语法树.h 的节点，为表达式/语句/声明/函数/结构体/枚举/匹配/遍历/容器字面量等写 PEG 规则 + 语义动作（构造 AST）。
- **S3.5（延后/可选）**：解释模式内建求值动作。

## 验证清单（每步）

- 工具/peg/测试.sh 保持通过（玩具文法 host+boot 一致）。
- 新步骤：小型文法用 `名:e`/`{…}` 验证；再上 日月 文法。
- 最终：解析全部 `示例/*.心`；与宿主前端结果对比（阶段目标）。
- 若改 自举/*.心 → `make 自举` 不动点 + `test_all23.ps1` 不回归。
