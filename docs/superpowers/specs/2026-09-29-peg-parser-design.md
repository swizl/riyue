# PEG 解析器生成器 + 模块系统 设计（阶段 A1）

> 主题：「用 日月 语言编写一个 PEG 语法解析器（识别语法、输出语法树），读取 词法+文法 规则文件，输出解析代码，再把 日月 语言移到这个之上」。
> 本文档：§1–§4 为总路线图；§5 起是本阶段 **A1（模块系统）** 的详细设计。

---

## 1. 总目标

用 日月 语言实现一个 PEG 解析器生成器：

- 输入一份「词法规则 + PEG 文法规则」文件；
- 模式一：**解释执行**该文法，把输入 token 流解析成**语法树**（真树对象）；
- 模式二：**生成 日月 专用解析代码**（递归下降）；
- 最终把 日月 语言本身的前端（宿主 `源/前端` 与自举 `自举/编译器.心` 的手写前端）**迁移到这套生成器之上**，达成真·自举。

## 5. A1 详细设计：模块系统

### 5.1 统一语义（宿主链与自举链必须一致）

- **语法（本阶段）**：只支持整模块导入
  ```
  导入 "路径";
  ```
  `as` 别名与选择性导入 `{ 函数1, 函数2 }`：本阶段**两面都明确报错「暂不支持」**（宿主在 `导入` 解析处新增拒绝，`编译器.心` 同样拒绝），避免静默分叉。别名/选择性导入的完整语义（D3/D6）延后；宿主原有的别名/选择性合并代码保留但不可达。
- **合并时机**：编译期合并（不是分别编译再链接）。被导入模块的 **函数 / 结构体定义 / 枚举定义 / 全局变量** 合入同一程序。
- **递归**：被导入模块自身的 `导入` 也要处理（深度优先，先并入依赖）。
- **环检测**：维护「正在导入」集合，命中即报错并终止。
- **去重**：同一文件被多次导入只并入一次（键 = 规范化后的绝对路径）。
- **冲突**：同名函数/全局/结构体/枚举 → **报错并终止**（不再静默覆盖）。
  - 例外：被导入模块中的 `主程序` 不参与合并（入口属于主文件）；主文件必须有自己的 `主程序`。
- **路径解析**：相对**导入者所在目录**解析；失败再回退到「输入文件目录」「可执行文件目录\标准库\」；仍找不到 → 报错。
- **函数顺序**：被导入模块的函数插到主文件函数**之前**（沿用宿主既有相对顺序）；入口按名字查找 `主程序`（见 D8）。

### 5.2 宿主侧修复清单（`源/`）

| # | 缺陷 | 修法 |
|---|---|---|
| **D1** | 导入信息只存分析器对象、不进 AST，导致嵌套导入完全失效 | `抽象语法树.h` 的 `程序` 增加 `导入列表/别名/选择` 字段；`语法分析器.cpp` 解析 `导入` 时同时写入 `程序`；`主程序.cpp` 把合并逻辑抽成**递归函数**，对每个 `模块程序->导入列表` 再递归 |
| **D2** | 无 in-progress 集合，递归后会死循环 | 合并函数携带共享状态：`正在导入`（in-progress，报错用）+ `已导入`（去重）；解析前 insert、完成后 erase |
| **D4** | 去重键是原始路径字符串（`..`/大小写/不同基准 → 同一文件合并两次） | `查找模块` 命中后用 `GetFullPathNameA` 规范化；去重键、`已导入` 集合、返回值统一用规范路径 |
| **D5** | 同名函数/全局/结构体/枚举静默覆盖 | 合并点做存在性检查并报错（含 `主程序` 例外规则） |
| **D7** | 路径基准是主文件目录而非导入者目录；标准库候选拼成 `标准库\标准库\…` | `查找模块` 参数化基准目录（导入者传入自身目录）；标准库候选改为 `程序目录\标准库\ + basename` |
| **D8** | 入口 = `函数列表.back()`，拆分后非常脆弱 | 入口改为**按名字查找 `主程序`**；找不到时回退到 `back()`（保持旧行为，零回归） |

> 不在 A1 范围（延后）：D3 别名语义、D6 选择性导入、D9 非 LLVM 模式的导入、D10 结构体继承/重名顺序、D11 边角语法。

### 5.3 编译器侧实现（`自举/编译器.心`）

`编译器.心` 目前是**单文件、两遍扫描**（第一遍收集全局与函数原型，第二遍发射函数体）。为最小改动，`导入` 用**文本包含（textual include）**实现：

1. 读主文件全文 → 得到源码字符串；
2. `处理导入(源码, 当前文件目录)`：扫描形如 `导入 "路径";` 的**整行**语句；
   - 解析路径（相对当前文件目录 → 输入目录 → 程序目录\标准库\）；
   - 去重（键 = 拼接后的路径字符串）+ 环检测（正在导入集合）；
   - 递归处理被导入文件内容，把该 `导入` 行替换为处理后的模块文本；
3. 把处理后的整段源码交给现有的两遍扫描（**无需改动词法/语法/AST 逻辑**）；
4. 找不到文件、循环导入 → 报错终止。

**与宿主顺序对齐**：`导入` 语句必须写在主文件**所有函数定义之前**（习惯上紧跟在全局声明之后），这样文本包含后被导入的函数自然排在主文件函数之前，与宿主「前插」顺序一致。

已知限制（写入 `progress.md` / 设计文档，不阻塞）：

- 只识别**整行** `导入 "…";`（不识别写在表达式中间或函数内的 `导入`）；字符串/注释里的 `导入 "…";` 若整行出现会误判（源码约定规避）。
- 去重键是「拼接后的路径字符串」而非完全规范化绝对路径；源码按规范化拼写导入即可与宿主一致。
- 行号/错误位置因文本包含而失真（可接受）。

### 5.4 `编译器.心` 文件拆分

全局变量声明必须出现在所有使用点之前，因此**全部全局仍留在主文件**；函数按职责拆出：

| 文件 | 内容 |
|---|---|
| `自举/编译器.心` | 全部全局声明 + `导入` 语句 + 两遍驱动 + 主程序（含入口） |
| `自举/词法.心` | 字符码/前进/判断空白/数字/字母/**下一个标记** 等词法 |
| `自举/发射.心` | 转义/字节转义/表与小工具/寄存器与标签/字符串常量表/发射前导/辅助函数定义/主程序入口 |
| `自举/语法.心` | 表达式链、语句、函数签名、闭包、控制流 等解析+发射 |

约束：

- 模块内函数被主文件或其它模块调用 → IR 允许前向引用，无需声明顺序；
- 主文件的 `主程序` 仍放在主文件**最后一个函数**（D8 落地后已不必要，但便于与现状对照）；
- 拆分**不得改变**任何发射逻辑（纯搬运），`make 自举` 不动点必须仍成立。

### 5.5 验证

1. **宿主修复后**：`make 日月.exe` 成功；6 个用 `导入` 的示例（模块测试/日志测试/测试运行器示例/标准库测试/综合语法测试/数学包测试）行为不变；`test_all23.ps1` 79/0。
2. **新增语义测试**（多文件小样例）：嵌套导入（A→B→C）、重复导入去重、循环导入（应报错）、同名冲突（应报错）。
3. **编译器加 `导入` 后**：`make 自举` 不动点成立。
4. **拆分后**：`make 自举` 不动点成立；`自举/` 下 ≥4 个 `.心` 文件；同一多文件程序在宿主链与 IR 链输出一致。

> 注：`示例/数学包测试.心` 是**既有坏例**（它调用的 `四舍五入/平方根/幂运算` 在 `标准库/数学.心` 中并不存在），不作为验收依据，也不在 A1 中修复。
